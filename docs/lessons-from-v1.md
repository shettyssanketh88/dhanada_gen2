# Lessons from Dhanada v1 (May 2026 – September 2026)

*Status: normative input to the v2 specification. Every item here is backed by a measurement made on v1 (memory notes, replay harness, `strategy_audit`, `hod_pm_ab`, or the 2026-09-07 research report). Items are written as rules v2 must satisfy, not as history.*

v1 was a ~40k-LOC Python/FastAPI platform with an event pipeline, a MetaController, a RiskEngine, a paper OMS, a kill switch, an LLM "trade planner", and a "learning engine". Its plumbing worked. It never found an edge, and the parts that were supposed to learn never ran. v2 keeps the plumbing lessons and discards the product.

## 1. What actually failed

| # | Failure | Evidence | Rule for v2 |
|---|---|---|---|
| F1 | **Traded where retail cannot win**: 1-minute to intraday cash equity with 0.5–0.75 % stops. | cost_R = cost % / stop % ⇒ 0.15 % / 0.75 % = 0.20R per trade; best gross edge found was +0.056R (hod_pm, ~11k OOS trades, 5.5σ) ⇒ net ≈ −0.13R. Entry-rule audit on 4,682 samples: median R:R 0.71 intraday vs 3.05 at a 5-day hold, *identical entries*. | Every strategy carries its cost equation. No sleeve is promoted unless gross expectancy ≥ 2× realised cost. Multi-day horizons are the default; intraday is a special case that must prove itself. |
| F2 | **One sleeve, one horizon, one asset class.** | Grinold: IR = IC × √breadth. v1 had a single live trigger family plus a passive beta book. | The desk is a *portfolio of sleeves* from day one: ≥ 2 horizons, ≥ 3 sleeves before real capital. |
| F3 | **Found an edge and did not build it.** Mid/small-cap cross-sectional momentum: +3.3 %/month excess (survivorship-caveated), flagged 2026-07-07, never shipped. | Memory: `alpha-research-findings`. | The research→promotion→deployment loop is a *first-class workflow with owners and SLAs*, not a backlog item. |
| F4 | **LLM in the wrong seat.** LLM proposed entries/stops/targets, then take/skip on a mechanical trigger. | Take/skip A/B (gpt-5.6-terra, 400 calls): +0.001R lift. Prompt anchoring: "max 5 %" ⇒ 5.1 % stops; "0.5–1.5 %" ⇒ 0.6 % stops. gpt-4o-mini proposed 0/24. External: KTD-Fin 9/10 frontier models negative stock-selection alpha; Alpha Arena GPT-5 −63 %. | **Agents decide categories; code decides numbers.** No price level, stop, size or threshold is ever produced by an LLM. Every LLM feature is A/B-tested against the mechanical baseline and the lift is a number. |
| F5 | **The learning loop was a stub.** `NoOpLearningEngine` in the live path; offline engine produced proposals nobody consumed. Post-trade reviews were written and never read. | Memory: `trading-status-and-next-levers`, `learning-engine-autotune-scope`. | The loop (review → hypothesis → pre-registered trial → gate → versioned change → deploy → decay monitor) is specified end-to-end with a named owner role for each hop, and it is exercised in CI with a synthetic trade before v2 trades paper. |
| F6 | **Reacted to daily P&L.** Config was changed after 1–3 sessions at least six times (07-20 … 08-08). | Memory: `intraday-r2-relaunch`, the "small samples burned us" note. SE of expectancy at n=11 ≈ 0.30R. | No parameter that affects trading changes without a pre-registered gate and a minimum trade count (MTRL). Agents are *forbidden* from acting on daily P&L; the spec encodes it as a policy rule. |
| F7 | **Backtest ≠ live.** Proxy backtest with idealised fills invented a mean-reversion edge that lost ₹10.5k in replay. Trailing stops and time stops were shipped, then three independent audits showed they subtract value. | Memory: `trading-status-and-next-levers`, `intraday-r2-relaunch`. | One simulation kernel shared by research, replay and paper; first-touch fills with same-bar stop/target ties counted as losses; realised-cost calibration from live fills; managed exits off unless a gate turns them on. |
| F8 | **Best-of-N selection.** The "squeeze" family looked +0.042R in-sample and died at +0.008R on holdout; a confidence-quartile split (t=1.7, post-hoc) was almost built on. | Memory: `intraday-r2-relaunch`. | Every backtest is a row in a trial ledger; Deflated Sharpe with the ledger's N is reported beside every Sharpe; holdout windows are declared before the run. |
| F9 | **Survivorship in the universe.** Universe chosen by today's liquidity = 5-year survivors. | Memory: `alpha-research-findings`. | Point-in-time universe and constituents, delisting history included, as a data requirement. |
| F10 | **Unmeasured slippage.** Feed ran in Kite `quote` mode (no bid/ask) for months; slippage was a 1 bp assumption. | Memory: `edge-versus-costs`. | Bid/ask captured from day one (Kite `full` mode); arrival vs fill logged on every order; realised cost per R is a dashboard number. |
| F11 | **Structural biases that guaranteed "don't trade".** Volume ratio not paced by session time; regime computed from a single-symbol proxy that could never read "trending"; strategy stats poisoned by an abandoned era; watchlist consulted alphabetically so movers were never reached; a hard-coded 5 % stop cap rejecting 111 setups/day. | Memory: `intraday-r2-relaunch` (v0.48.3, v0.49.1, v0.49.12). | Every input an agent sees is a *tested feature* with a unit test on its distribution (no feature may be degenerate). Agent inputs are versioned and replayable. |
| F12 | **Governance lost mid-trade.** A filled plan stopped "governing" its position after 5 minutes; the legacy ATR stop re-engaged; a re-plan could mint an opposite-direction plan over an open position. | Memory: `intraday-r2-relaunch` (v0.49.4). | A trade is one entity with one owner and one state machine from idea to archive. Nothing else may act on that position. |
| F13 | **Silent operational failures.** Wrong `.env` file; `docker cp` into a running prod container; `release.yml` built images without running tests; CHECK constraints rejecting every REST quote for a morning; token collisions between two consumers of one Kite key; `Decimal` not JSON-serialisable blocking every research tool. | Memory: `intraday-r2-relaunch`, `sidecar-token-collision`, `edge-phase0-implemented`. | Ops is an agent role with runbooks-as-skills, health checks are contracts, and "nothing runs on the VM that CI did not build and test". One Kite token, one consumer of it. |
| F14 | **Static rule strategies with no adaptation and no context.** Strategies were pure functions of price; the LLM planner saw no price structure until v1.9.0. | Memory: `intraday-r2-relaunch` (08-08). | Mechanical rules stay mechanical, but the *research* around them is continuous and agent-driven; catalysts, regime and breadth are first-class categorical features. |
| F15 | **Development environment friction.** OneDrive corrupted git objects; subagents stalled on the OneDrive path; no local Python; tests only in CI. | Memory: `where-work-happens`, `edge-phase0-implemented`. | v2's repo keeps `.git` off OneDrive (already done: `~/git-repos/dhanada-v2.git`), agents work in a scratch copy, and CI is the only verifier. |

## 2. What worked and must be kept (as knowledge, not as code)

- **Pre-registered holdouts** for hod_pm (four windows, never-seen data) and the A/B rig that made the LLM's value-add a number. This is the research discipline v2 formalises.
- **Bracket-only exits**: 8 of 11 first-session exits resolved on stop/target; drift to EOD disappeared once trailing/time stops were removed.
- **Fail-open selectors, crash-safe consumers, clamp-to-open-quantity on exits, idempotent fill ids.**
- **Single-token Kite design** (v0.49.8): one OAuth login serves WebSocket ticker and REST quotes.
- **Paper OMS with marketable-limit entries and rejection of non-marketable limits** (honest fills).
- **Statutory cost model** checked against Zerodha's published schedule (v0.51.3).
- **Deployment model**: Docker Compose on one Mumbai VM, native PostgreSQL, ghcr.io images, `age`-encrypted backups (ADR-005). Nothing about it caused a failure.
- **Data**: 12.9M 1-min bars, 208 symbols, 240 sessions; 507k daily bars 2016–2026; backfill tools are idempotent. v2 imports this data; it does not re-download it.
- **The 2026-09-07 research report** (`docs/research/2026-09-07-path-to-edge.md` in v1) and the EDGE gate register G1–G9. v2 adopts the gate philosophy and the evidence ranking of strategies.

## 3. The one-paragraph diagnosis

v1 was built as a *platform* first and a *trading business* second. It had every component a trading system is supposed to have, but the components were connected by static code paths that nobody owned once shipped: the learning engine was a stub, the reviewer's output went nowhere, the researcher (a human with Claude in a terminal) ran one experiment per live day, and the LLM was asked to do the one thing the evidence says it cannot do — pick price levels. v2 inverts this: the *organisation* is the product. Roles with memory own the research, the trades, the risk, the review and the operations, continuously, and the static code is reduced to the things that must be deterministic — execution, accounting, risk policy, simulation and data.
