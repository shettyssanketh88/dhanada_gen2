# Zerodha Kite Connect: execution, data and regulatory constraints for a retail automated desk

*Research date: 2026-09-20. Web research (Kite Connect docs and forum, SEBI/NSE circulars, Zerodha Z-Connect and support articles, practitioner reports). Feeds `specs/000-platform/execution.md`.*

## 1. Kite Connect API v3 (2026)

**Plans and pricing.** Two plans: *Kite Connect Personal* (free; orders, positions, holdings, funds, no market data) and *Kite Connect* (₹500/month per API key; includes live WebSocket data and historical candles; the old ₹2,000 historical add-on was removed Feb 2025). No sandbox exists. [FAQ](https://support.zerodha.com/category/trading-and-markets/general-kite/kite-api/articles/kite-connect-api-faqs), [Z-Connect](https://zerodha.com/z-connect/updates/free-personal-apis-from-kite-connect), [forum](https://kite.trade/forum/discussion/14806/historical-data-is-now-free-with-base-kite-connect-subscription)

**Order placement** (`POST /orders/:variety`). Varieties: `regular`, `amo`, `co` (cover order; second leg carries `parent_order_id`), `iceberg` (2–50 legs, quantity/legs per slice; counts as one order for rate limits), `auction`. Bracket orders (BO) are not available via API. Validity `DAY`/`IOC`/`TTL` (minutes via `validity_ttl`). `autoslice=true` splits quantities above the freeze limit into up to 10 slices, each with its own `order_id` or error. Max 25 modifications per order. Status flow: PUT ORDER REQ RECEIVED → VALIDATION PENDING → OPEN PENDING → OPEN → (MODIFY…) → COMPLETE / CANCELLED / REJECTED. [Orders docs](https://kite.trade/docs/connect/v3/orders/)

**Market protection.** Since the SEBI rules, MARKET and SL-M orders must carry `market_protection`; `0` is rejected, `-1` = system-chosen band (order converts to limit at LTP ± band). MCX does not allow market orders / IOC in the algo segment. [Forum 15912](https://kite.trade/forum/discussion/15912/preparing-to-comply-with-sebis-retail-algo-rules-static-ip-ratelimits-order-types), [Forum 15350](https://kite.trade/forum/discussion/15350/notes-on-the-nse-circular-prescribing-operating-procedures-for-api-usage)

**Tags.** `tag` is a free alphanumeric string, max 20 chars, echoed back in the order book. Zerodha documents no idempotency/duplicate suppression on it. [Orders docs](https://kite.trade/docs/connect/v3/orders/), [tag thread](https://kite.trade/forum/discussion/14292/place-order-tag-and-tags)

**Margins.** `POST /margins/orders` (per-order) and `POST /margins/basket` (portfolio-aware, considers existing positions and pending orders). [Basket margins](https://kite.trade/forum/discussion/12661/api-to-know-final-margin-for-basket-order), [example](https://github.com/zerodha/pykiteconnect/blob/master/examples/order_margins.py)

**GTT.** `single` and `two-leg` (OCO). Validity one year; max 500 active per account; **CNC/NRML only, not MIS**; no margin blocked; on trigger a *LIMIT* order is placed (can be rejected on margin/circuit); inactive GTTs visible for 7 days via API. Two-leg GTT is Zerodha's official substitute for BO: it works as a broker-side stop/target bracket only for positional (CNC/NRML) exposures, never for intraday MIS. [GTT docs](https://kite.trade/docs/connect/v3/gtt/), [validity](https://support.zerodha.com/category/trading-and-markets/charts-and-orders/gtt/articles/what-is-the-validity-of-a-gtt-order), [GTT FAQ](https://support.zerodha.com/category/trading-and-markets/charts-and-orders/gtt/articles/what-is-the-good-till-triggered-gtt-feature), [OCO thread](https://kite.trade/forum/discussion/9299/set-a-stop-loss-and-target-at-same-time)

**Order updates.** Two channels: (a) HTTP postbacks to a `postback_url` with SHA-256 checksum (order_id + timestamp + api_secret) — intended for multi-user platforms, only for orders placed through that app, no documented retry semantics; (b) order postbacks over the ticker WebSocket as JSON text frames (`type: "order"`), for *all* orders regardless of origin. Both are streaming: updates during a disconnect are lost, there is no replay. Zerodha staff explicitly recommend treating updates as events and then fetching `/orders`, not relying on them as the ledger. [Postbacks](https://kite.trade/docs/connect/v3/postbacks/), [guarantee thread](https://kite.trade/forum/discussion/11290/are-order-updates-on-web-socket-guaranteed), [missed COMPLETE](https://kite.trade/forum/discussion/11194/on-order-update-order-complete-updates-not-being-received)

**WebSocket ticker.** Modes `ltp` (8 B), `quote` (44 B), `full` (184 B, 5 bid + 5 ask depth, 12 B per level). Max 3,000 instruments per connection, 3 connections per API key; 1-byte heartbeat every few seconds; index packets 32 B. [WS docs](https://kite.trade/docs/connect/v3/websocket/)

**REST quotes.** `/quote` (500 instruments, includes 5-level depth), `/quote/ohlc` and `/quote/ltp` (1,000). Instrument master CSV `/instruments` regenerated once daily (fetch ~08:30 IST). [Quotes docs](https://kite.trade/docs/connect/v3/market-quotes/)

**Historical.** Intervals minute…60minute, day; `continuous=1` for expired futures; `oi=1`. Max span per request: minute 60d, 3/5/10-minute 100d, 15/30-minute 200d, 60-minute 400d, day 2000d. No tick history. [Historical docs](https://kite.trade/docs/connect/v3/historical/), [limits thread](https://kite.trade/forum/discussion/12988/historical-api-interval-limit)

**Rate limits.** Quote 1 req/s, historical 3 req/s, orders 10/s, everything else 10/s; 400 orders/min; 5,000 orders/day per account; the 10 OPS cap is per client ID (all apps combined) and rejected requests count; excess gets HTTP 429. [Exceptions docs](https://kite.trade/docs/connect/v3/exceptions/), [limits](https://kite.trade/forum/discussion/6329/kiteconnect3-api-limits)

**Login/2FA.** Access token needs a browser login + TOTP each day; tokens are flushed early morning (~6 AM) tied to EOD processes and cannot be moved. Logging into Pi/NEST or logging out anywhere invalidates the token (`TokenException`, HTTP 403). Zerodha's stated position: fully automated login was "never allowed" and violates API terms; TOTP-seed automation (pyotp) is widespread but is a terms-of-use risk, not a supported path. [TOTP thread](https://kite.trade/forum/discussion/10391/mandatory-totp-for-all-kite-connect-apps), [token FAQ](https://support.zerodha.com/category/trading-and-markets/alerts-and-nudges/kite-error-messages/articles/incorrect-api-key-error)

**Official kite-mcp-server.** Tools: quotes/LTP/OHLC/historical/instrument search, profile/margins/holdings/positions/MF holdings, `place_order`/`modify_order`/`cancel_order`/orders/trades/order history, and GTT place/modify/delete. Auth via a `login` tool that returns a Kite authorization link (same daily-session model). Modes stdio/http/sse/hybrid; `EXCLUDED_TOOLS` env for read-only instances. Hosted `https://mcp.kite.trade/mcp` needs no API key but **excludes destructive order tools**; self-hosted with your own key exposes full order placement. [Repo](https://github.com/zerodha/kite-mcp-server), [README](https://github.com/zerodha/kite-mcp-server/blob/master/README.md)

## 2. SEBI retail algo framework and related market rules

**Circular** SEBI/HO/MIRSD/MIRSD-PoD/P/CIR/2025/0000013 (4 Feb 2025); implementation moved from 1 Aug 2025 → 1 Oct 2025 → **1 Apr 2026** (circular …/2025/132, 30 Sep 2025). [SEBI Feb 2025](https://www.sebi.gov.in/legal/circulars/feb-2025/safer-participation-of-retail-investors-in-algorithmic-trading_91614.html), [extension](https://www.sebi.gov.in/legal/circulars/sep-2025/extension-of-timeline-for-implementation-of-sebi-circular-dated-february-04-2025-on-safer-participation-of-retail-investors-in-algorithmic-trading-_96979.html), [NSE standards INVG67858](https://nsearchives.nseindia.com/content/circulars/INVG67858.pdf)

- **Threshold:** 10 orders/second per exchange per segment per client, counting placements, modifications and cancellations. ≤10 OPS: self-developed algo needs no strategy registration; the **broker tags orders with a generic exchange Algo-ID** (client passes nothing). >10 OPS: registration through the broker (Zerodha: support ticket with strategy write-up, risk write-up, auditor certificate per Annexure 7) and a unique exchange Algo-ID. [Z-Connect NSE overview](https://zerodha.com/z-connect/general/a-comprehensive-overview-of-nses-circular-on-the-new-retail-algo-trading-framework), [Forum 15350](https://kite.trade/forum/discussion/15350/notes-on-the-nse-circular-prescribing-operating-procedures-for-api-usage)
- **Static IP:** mandatory for API order placement from 1 Apr 2026 regardless of frequency; one primary + one secondary IP, IPv4/IPv6, changeable once per calendar week, registered at developer-profile level (Zerodha rolled it out ~15 Mar 2026); non-matching source IP → order rejected; data/WebSocket/order-book endpoints unaffected; sharing only with immediate family. [Static IP article](https://support.zerodha.com/category/trading-and-markets/general-kite/kite-api/articles/static-ip), [In The Money](https://inthemoneybyzerodha.substack.com/p/sebi-algo-trading-changes-april-2026)
- **White box vs black box:** white box = logic disclosed and replicable (execution algos); black box = logic undisclosed, provider must be a SEBI-registered Research Analyst and keep a research report per strategy. Algo *providers* (vendors) must be empanelled with exchanges; brokers are the principal, must keep audit trails, OAuth/2FA, and a kill switch. [Z-Connect SEBI explainer](https://zerodha.com/z-connect/business-updates/explaining-the-latest-sebi-algo-trading-regulations), [AlgoBulls](https://algobulls.com/blog/industry-insights-and-updates/sebi-new-algotrading-regulations-for-retail-investors-2026)
- **Auto square-off (Zerodha):** equity MIS 3:25 PM, F&O MIS 3:26 PM (revised Dec 2025); ₹50 + GST per squared-off order. [Z-Connect](https://zerodha.com/z-connect/updates/changes-to-the-auto-square-off-timings-for-equity-and-fo), [support](https://support.zerodha.com/category/trading-and-markets/trading-faqs/market-sessions/articles/intraday-auto-square-off-timings)
- **Settlement:** T+1 is the default; optional T+0 was phased in for the top-500 by market cap from 31 Jan 2025 (brokers may charge differential brokerage). [Moneylife](https://moneylife.in/article/sebi-introduces-optional-t0-settlement-for-top500-stocks/75841.html), [Business Standard](https://www.business-standard.com/markets/news/market-regulator-sebi-widens-scope-of-t-0-settlement-to-top-500-stocks-124121000906_1.html)
- **Peak margin:** full SPAN+exposure upfront; from 1 Apr 2026 Zerodha charges ₹40/order on intraday F&O if the 50% cash-collateral rule is not met. [Business Standard](https://www.business-standard.com/markets/news/zerodha-doubles-brokerage-fees-on-select-f-o-trades-from-april-1-report-126032500517_1.html), [Bajaj peak margin](https://www.bajajbroking.in/blog/sebi-peak-margin-rules)
- **Expiries and lots:** weekly expiry only on one benchmark per exchange (Nifty on NSE, Sensex on BSE) since Nov 2024; NSE expiries moved to **Tuesday**, BSE to **Thursday** from 1 Sep 2025. Lots: Nifty 75→65, Bank Nifty 35→30 from Jan 2026 series. Freeze quantity Nifty 1,800 (effective 1,755 at lot 65); new freeze limits from 1 Sep 2026 (Nifty/FinNifty 1,800; Bank Nifty/Next 50 600; Midcap 2,800). [Ventura](https://www.venturasecurities.com/blog/changes-in-expiry-nse-and-bse/), [HDFC Sky lots](https://hdfcsky.com/news/nse-revises-market-lot-sizes-for-major-index-derivatives-effective-january-2026), [Choice freeze](https://choiceindia.com/news/nse-fo-quantity-freeze-limits-september-2026)

## 3. Zerodha cost structure after Budget 2026 (STT change 1 Apr 2026)

STT changed only for F&O: futures 0.02%→0.05% (sell), option premium 0.1%→0.15% (sell), exercise 0.125%→0.15% of intrinsic. Equity delivery 0.1% both sides, intraday 0.025% sell unchanged. [STT bulletin](https://zerodha.com/marketintel/bulletin/445377/revision-in-stt-securities-transaction-tax-from-1st-april-2026), [charges page](https://zerodha.com/charges/)

Round-trip cost as % of one-side notional (NSE, computed from the charges page; brokerage lower of 0.03%/₹20 per executed order, flat ₹20 for options; GST 18% on brokerage+exchange+SEBI; SEBI ₹10/crore):

| Segment | Brokerage | STT | Exch txn (x2) | Stamp (buy) | GST | **Round trip** |
|---|---|---|---|---|---|---|
| Equity delivery | 0 | 0.20% | 0.00614% | 0.015% | ~0.001% | **~0.22%** (+₹15.34 DP on sell) |
| Equity intraday (₹1L ticket) | ₹40 = 0.04% | 0.025% | 0.00614% | 0.003% | ~0.008% | **~0.08%** (≈0.11% on small tickets where 0.03% binds; ≈0.045% at ₹5L) |
| Index futures (Nifty, ~₹16L notional) | ₹40 ≈ 0.0025% | 0.05% | 0.00366% (0.00183%/side) | 0.002% | ~0.001% | **~0.06%** (was ~0.03% pre-April; STT is now >80% of cost) |
| Options (per ₹6,500 premium lot) | ₹40 = 0.62% of premium | 0.15% | 0.071% (0.03553%/side) | 0.003% | ~0.12% | **~0.96% of premium** (~0.33% at ₹50k premium; +0.15% of intrinsic if exercised) |

Add ₹50+GST per auto-squared-off MIS order and ₹40 brokerage on intraday F&O if <50% cash collateral.

## 4. Data sources

- **Daily OHLCV:** Kite historical (day candles, 2000d/request, 3 req/s, ₹500/month); NSE CM bhavcopy archives (free) via [NseIndiaApi](https://github.com/BennyThadikaran/NseIndiaApi), [nsefin](https://pypi.org/project/nsefin/), [nse-bse-api](https://github.com/bshada/nse-bse-api) (NSE site throttles ~3 req/s and blocks bots).
- **Point-in-time constituents:** NSE `IndexInclExcl.xls` (archives.nseindia.com) is authoritative 1998–Jul 2020 only; after that use niftyindices.com monthly "Indices Market Capitalization" reports (PDF scraping) or Wayback diffs of the constituent CSV; Kite has nothing. [Forum 7379](https://kite.trade/forum/discussion/7379/historical-constituents-of-nse-indices), [Marketcalls method](https://www.marketcalls.in/llm-models/how-to-build-survivorship-bias-free-nifty-50-historical-data-using-grokbot.html), [PIT backtester repo](https://github.com/rishabhjain0295-web/nifty500-momentum-backtest)
- **Delisted/survivorship-free:** EODHD covers 1,700+ NSE names including delisted from Dec 2006 (paid); broker-published delisted lists (e.g. [Nirmal Bang](https://www.nirmalbang.com/equity/bse-nse-delisted-companies.aspx)) for cross-checks. [EODHD](https://eodhd.com/financial-academy/financial-faq/survivorship-bias-free-financial-analysis)
- **Corporate actions, results calendar, announcements:** NSE's undocumented JSON endpoints wrapped by the libraries above (`get_corporate_actions`, `get_upcoming_results`, `get_corporate_announcements`); no official public API.
- **Bid/ask:** live 5-level depth from Kite `full` mode or `/quote` (no history); historical tick/depth only from authorised vendors (TrueData L1 NSE/L2 BSE, GDFL native tick with ms timestamps) or NSE's paid TBT feed. [TrueData](https://www.truedata.in/market-data-apis), [GDFL](https://globaldatafeeds.in/global-datafeeds-nsebse-mcx-authorized-data-vendor/), [NSE real-time data](https://www.nseindia.com/static/market-data/real-time-data-subscription)

## 5. Practitioner reliability reports (2025–2026)

- **Timeouts that still fill:** `NetworkException`/timeouts on place-order where the order later appears in the book (30 s to 2+ min later). Zerodha's guidance: "check orderbook and retry for all non-400 write API responses", using unique tags to find the order. Naive retry-on-timeout is the top cause of duplicates. [Forum 6865](https://kite.trade/forum/discussion/6865/why-order-failed-in-api-but-actually-trigered), [duplicates](https://kite.trade/forum/discussion/9444/automatically-placing-duplicate-orders)
- **Token invalidation:** fresh tokens dying mid-session because another login (Pi/NEST/logout, second app under one client ID) invalidated the session. [Forum 12464](https://kite.trade/forum/discussion/12464/newly-generated-access-token-becomes-invalid-when-taking-a-new-position), [Forum 14628](https://kite.trade/forum/discussion/14628/kiteconnect-exceptions-tokenexception-token-is-invalid-or-has-expired)
- **WebSocket:** 1006 unclean disconnects reported through Dec 2025; order updates missed during any gap; no replay. [WS error tag](https://kite.trade/forum/discussions/tagged/websocket-error/p1), [Forum 7781](https://kite.trade/forum/discussion/7781/websocket-connection-loss-effect-on-on-order-update-ws-data-api)
- **Static-IP rejections** when cloud egress/NAT IP differs from the whitelisted one (Heroku/Railway users). [QuotaGuard](https://www.quotaguard.com/blog/kite-connect-static-ip)

## Execution-layer design constraints

1. All order endpoints must egress from one whitelisted static IP (primary + optional secondary, IPv4 or IPv6); pin the VM's IP and alert if the observed egress IP drifts. Data endpoints may use any IP.
2. Global token-bucket per client ID: ≤10 order actions/s across all apps (place+modify+cancel, rejections included), ≤400/min, ≤5,000/day; treat 429 as back-pressure, never as "not placed".
3. Stay under 10 OPS per exchange/segment by design (queue + pacing) so the generic Algo-ID path applies; no client-side algo ID field exists.
4. Every order carries a unique ≤20-char alphanumeric `tag` (e.g. base36 of a client order id); the tag is the reconciliation key, not an idempotency guarantee.
5. Place-order is not idempotent: on any non-400 failure or timeout, poll `/orders` filtered by tag for ≥2 min before retrying; persist "intent → sent → acked" state before the HTTP call.
6. Treat WebSocket order postbacks and HTTP postbacks as hints; the order book (`/orders`, `/orders/:id/trades`) is the source of truth; reconcile on every update event, on WS reconnect, and on a fixed timer.
7. MARKET/SL-M orders must set `market_protection=-1` (or a band); never 0. Prefer limit/SL-L with explicit prices for determinism.
8. Broker-side brackets: use two-leg GTT (OCO) only for CNC/NRML positions (≤500 active, 1-year validity, places a LIMIT order on trigger, can be rejected); intraday MIS stops must be system-managed SL orders with a local watchdog.
9. Hard deadline: flatten MIS before 3:25 PM (equity) / 3:26 PM (F&O) or eat ₹59/order; the engine's own square-off must run earlier (e.g. 3:15) and verify via positions.
10. Session lifecycle: one manual TOTP login per day before 09:00 IST; a single session per client ID (no concurrent Kite/Pi/NEST logins from ops); on `TokenException` halt order flow and page — do not auto-relogin with stored TOTP seeds (terms-of-use violation).
11. Respect quantity freeze limits (Nifty 1,755 effective) with `autoslice` or manual slicing; keep lot sizes (Nifty 65, Bank Nifty 30) and expiry calendars (NSE Tue, BSE Thu) as data, not code.
12. Check `/margins/basket` before multi-leg entries; assume 50% cash collateral or budget ₹40/order brokerage on intraday F&O.
13. Data plane: ≤3 WS connections/key, ≤3,000 instruments each; REST quotes ≤1 req/s (500 instruments), historical ≤3 req/s with per-interval span caps; refresh instrument master daily ~08:30.
14. Cost model must use post-April-2026 numbers: ~0.06% round trip on index futures, ~0.08–0.11% equity intraday, ~0.22% equity delivery, ~0.3–1% of premium on options, plus slippage from market-protection conversions.
15. Backtests must use PIT universes (IndexInclExcl to 2020 + niftyindices monthly reports after) and a delisted-inclusive price source; Kite historical alone is survivorship-biased.
