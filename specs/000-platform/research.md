# Research pipeline, trial ledger and gates

*Companion to `spec.md` (DH2-RSH-*). Implements constitution Articles II and III. Sources: v1 EDGE spec WP0.3/WP0.4/WP5.5 (formulas retained), Bailey & López de Prado (DSR/PSR/MTRL), Kinlay 2026 (log N and k), Vaccaro ICML 2026 (pre-registration for agents), KTD-Fin (masking), the 2026-09-07 path-to-edge report.*

## 1. Why the research loop is the product

v1 found an edge (mid/small-cap momentum) and never built it, because research was a human with a terminal running one experiment per live day. v2 makes research a continuous, owned process: hypotheses are generated by the Post-Trade Reviewer, the Market Intelligence Analyst and the Principal; the Quant Researcher pre-registers and runs trials nightly; the Validation Reviewer red-teams; gates decide; sleeves are born, paused and retired by evidence.

## 2. The pipeline

```
backlog item ──G0──► pre-registration (committed) ──► trial (ledger row opened) ──► report (DSR, N, k, MTRL, cost_R)
      ▲                                                                                     │
      │                                                                                     ▼
 Post-Trade Reviewer / Market Intel / Principal                              Validation Reviewer verdict
                                                                                            │
                                            reject ◄───────────────┬────────────────────────┤
                                            request_holdout ◄──────┘                        ▼ accept
                                                                          gate G1/G2 evaluated by code
                                                                                            ▼
                                                                          paper sleeve created (status active, paper account)
                                                                                            ▼
                                                                    G3 (paper → keep) ──► G5 (capital, Principal signature)
```

## 4. Pre-registration

Committed to `research/experiments/<experiment_id>/preregistration.md` **before** the trial runs; the ledger checks the file's git SHA is an ancestor of the run's `code_sha`.

```markdown
---
experiment_id: mom_core_pit_v1
backlog_id: B-001
registered_at: 2026-10-06T21:10:00+05:30
registered_by: quant_researcher@v3   # role@version
hypothesis: "…one falsifiable sentence…"
universe: {source: pit_liquidity_rank, rank_by: turnover_20d, top_n: 350, exclude: nifty100, as_of: rebalance_date}
data: {prices: daily_bars_v2_delisting_inclusive, from: 2016-01-01, to: 2026-08-31}
splits: {in_sample: [2016-01-01, 2022-12-31], holdout: [2023-01-01, 2026-08-31]}
parameters_fixed: {formation_months: [3, 6], skip_months: 0, hold_months: 1, top_k: [30, 50], ma_overlay_months: 10}
parameter_grid_size: 4                # N contribution of this registration
aggregation_plan: "report each cell; no blending"   # k = 1
cost_model: {product: CNC, rates_as_of: 2026-04-01, slippage: liquidity_class_model_v1}
metrics: [net_alpha_vs_nifty500, dsr, psr, mtrl, max_dd, turnover, cost_r_equivalent]
kill_criteria: "net alpha ≤ 0 in ≥ 2 of 5 holdout years, or DSR ≤ 0.5"
masking: {tickers: true, dates: true}  # for any LLM-touched step
---
```

A run whose parameters differ from the registered set is refused by the ledger (`DH2-RSH-003`). Changing the plan means a new registration id, which increments N.

## 5. Trial ledger

Table `research_trials` (adopted from v1 WP0.4 with additions):

| Column | Notes |
|---|---|
| `id`, `experiment_id`, `preregistration_sha`, `backlog_id` | identity |
| `tool`, `sleeve_id`, `family`, `hypothesis` | |
| `params` (JSONB, `jsonable`-converted), `params_hash` (sha256 canonical JSON) | N = distinct `params_hash` per experiment |
| `aggregation_depth_k` | number of parameter cells blended into the reported figure; 1 by default |
| `universe`, `window_from`, `window_to`, `is_holdout` | holdout declared before run |
| `n_trades`, `exp_r`, `win_rate`, `t_stat`, `sharpe_daily`, `n_days`, `skew`, `kurtosis`, `psr`, `dsr`, `sr_star`, `n_trials_at_eval`, `mtrl_days`, `max_dd`, `median_cost_r`, `gross_exp_r`, `net_exp_r` | results |
| `zero_alpha_ref` | id of the calibration run this trial is compared against |
| `code_sha`, `data_snapshot_id`, `status` (`running|completed|failed`), `notes`, `created_at`, `updated_at` | provenance |

Formulas (normative, from v1 WP0.4; `Φ` standard normal CDF, `γ = 0.5772156649`):

- `SR* = sqrt(var_sr) × [(1 − γ) Φ⁻¹(1 − 1/N) + γ Φ⁻¹(1 − 1/(N e))]`, `SR* = 0` for N = 1.
- `PSR(SR; SR_b) = Φ((SR − SR_b) √(T − 1) / √(1 − γ₃ SR + ((γ₄ − 1)/4) SR²))`.
- `DSR = PSR(SR; SR*)`.
- `MTRL = 1 + (1 − γ₃ SR + ((γ₄ − 1)/4) SR²) (Z_α / (SR − SR_b))²`, `None` when `SR ≤ SR_b`.
- Daily return series for trade-based sleeves: per-IST-date sum of R.

Every research CLI (`backtest`, `replay`, `audit`, `ab_test`) requires `--experiment` and refuses to load data without an open trial row (`DH2-RSH-001`). Failure paths mark the trial `failed`; a trial never stays `running` after the process exits.

## 6. Zero-alpha calibration

For each research tool, `research:calibrate_zero_alpha(experiment_id)` reruns the identical pipeline on (a) block-shuffled returns and (b) synthetic zero-drift series with matched volatility, for the same parameter grid, and records the distribution of the best cell's Sharpe. A trial's headline is reported alongside the calibration percentile ("a best-of-4 Sharpe of 0.9 sits at the 62nd percentile of zero-alpha runs"). Kinlay's point: two integers (N and k) explain most of an agent's reported Sharpe; the calibration makes that visible.

## 7. Masking and leakage controls

- Any step where an LLM touches historical data (feature generation, catalyst tagging on history, review of backtest trades) uses masked tickers and shifted dates (KTD-Fin), and the masking map is stored with the trial.
- All dated data is point-in-time: announcements by `published_at`, fundamentals as filed, universe as of date, last bar excluded if incomplete.
- The Validation Reviewer's checklist includes a lookahead test: rerun with the holdout window shifted forward by one day; results must not improve materially.

## 8. Validation Reviewer checklist (structured)

| Check | Pass condition |
|---|---|
| `prereg_exists` | Registration committed before run SHA |
| `params_match` | Run params ⊆ registered grid |
| `holdout_untouched` | Holdout window absent from all prior trials in the experiment's lineage |
| `universe_pit` | Universe built as-of dates; delisting table applied |
| `costs_realistic` | Cost model matches product and date; slippage model named |
| `fills_conservative` | First-touch, same-bar tie as loss |
| `n_k_logged` | N and k present; DSR uses ledger N |
| `zero_alpha_compared` | Calibration percentile reported |
| `regime_coverage` | Trades span ≥ 2 regime labels, each ≥ 20 % |
| `lap_control` | For LLM-touched steps: masking applied |
| `attribution` | For positional sleeves: return split into market/style/selection |
| `stability` | Year-by-year (or window-by-window) sign consistency reported |

Verdict `accept` requires all pass; `request_holdout` names a fresh window; `reject` lists failing checks. Two rounds maximum (`DH2-ORG-007`).

## 9. Gates (normative)

| Gate | Criteria |
|---|---|
| **G0** hypothesis → registered | Backlog item complete (statement, universe, horizon, cost model, kill criteria); not on the parked list |
| **G1** harness → paper (positional) | Net alpha vs benchmark > 0 in ≥ 4 of 5 holdout years; DSR > 0.5 at ledger N; max DD documented and accepted in writing by the Principal; turnover and cost drag reported |
| **G2** harness → paper (intraday/swing) | Net expR > 0 in every declared holdout window; pooled t > 2.5; n ≥ 300 trades; median cost_R ≤ 0.10; where the thesis is a filter, filtered beats unfiltered in every window; trigger-hour histogram sane |
| **G3** paper → keep | ≥ 100 trades (intraday/swing) or ≥ 6 rebalances (positional) across ≥ 2 regimes; net expR > 0 with t > 1 on realised costs; median cost_R ≤ 0.5 × gross expR; bracket exits ≥ 95 % (intraday); paper tracks harness within tolerance |
| **G4** enable an LLM feature | With-arm minus without-arm > 0.03R, t > 2 on the difference, ≥ 300 trades per arm on the same candidates (shadow design) |
| **G5** sleeve → real capital | G3 held; sleeve DSR > 0.5; governor never bypassed (log evidence); kill drill passed on current release; ≥ 3 sleeves at G3 across ≥ 2 horizons; portfolio DSR > 0 with correlation matrix reported; Principal signature; initial allocation ≤ min(₹100,000, 10 % of paper capital); order of first capital: positional core, then index futures, intraday last |
| **G6** lesson → validated | Lesson's implied categorical rule improves expectancy on a pre-registered holdout (t > 1.5, ≥ 100 trades); otherwise `retired` |

Changing a threshold after seeing data requires a new gate id (`G2-2027a`) and the Principal's approval; the register in `memory/desk/gates.md` is the log.

## 10. Sleeve lifecycle

`proposed → harness_validated (G1/G2) → paper (active) → capital_candidate (G3) → live (G5) → reduced/paused (governor) → retired (decay or failed re-validation)`

Each sleeve has `memory/desk/sleeves/<id>.md` (thesis, evidence, parameters by reference, status history) and `engine/sleeves/<id>/` (signal engine, config schema, tests, evals). Retirement is a PR that archives both.

## 11. Research compute and safety

- Backtests run in a sandbox (Claude Code sandbox or a dedicated research container) with read-only access to the Parquet store and write access only to `research/experiments/<id>/artefacts/`; never in the trading process (DH2-DEV-004).
- Research data snapshots are immutable and id'd (`data_snapshot_id`) so a trial is reproducible.
- Nightly research shift budget: USD 10 (`[NC-3]`); the Researcher plans its trial queue against the budget and records what was deferred.

## 12. Acceptance scenarios

- **R1** Given no pre-registration file, When `backtest --experiment x` runs, Then it exits before loading data with `preregistration_missing`.
- **R2** Given a registered grid of 4 cells, When a fifth parameter set is passed, Then the ledger refuses with `params_not_registered`.
- **R3** Given an experiment with 12 completed trials, When a report is produced, Then it shows DSR computed with N = 12 (distinct hashes), k, PSR, MTRL and the zero-alpha percentile.
- **R4** Given a `PromotionProposal`, When the Validation Reviewer runs, Then a `ReviewVerdict` with all 12 checks is stored before any gate evaluation, and a `request_holdout` creates a new registration.
- **R5** Given a `hypothesis` lesson, When its G6 trial fails, Then the lesson is `retired` and the backlog item is `falsified`.
